# 03. 数据模型与初始化迁移

> 本章定位:把当前 `app/models/` 已有的 19 张表梳理清楚,并把本轮 v2.0
> 新增的 P1 表规划出来。**所有表都通过 Alembic 迁移**,不再 `create_all`。
> 当前 `4bb73fc2e250_initial_schema.py` 是 `Base.metadata.create_all` 的占位,

## 1. 命名约定

- `sys_*` — 身份/系统级表(账号、家庭、邀请、渠道、上传)
- `scn_*` — 业务场景表(赛季、任务、特权、币、主题、模板、新手、通知等)
- 主键: **UUID 字符串**(`UUIDPrimaryKeyMixin`),不在 DB 端做自增
- 时间: `TimestampMixin`(`created_at` / `updated_at`)
- 外键: 全部 `String(36)`,显式 `ondelete` 策略

## 5. 迁移策略

### 5.1 现状

- `alembic/versions/4bb73fc2e250_initial_schema.py` 用 `Base.metadata.create_all` 一次性建表。
  对于开发环境 OK,但**不**符合"显式迁移"规范。

### 5.2 本轮 v2 行动

1. **保留** `4bb73fc2e250_initial_schema.py` 作为基线,
   但把它的实现改为对每张 `sys_*`/`scn_*` 现有表**显式 `op.create_table`**,
   与当前 ORM 一一对应(防止 `create_all` 自动推断漏掉 comment / index / check)。
2. **新表全部走 `alembic revision`**:
   - `2026xxxx_add_task_template_library.py`
   - `2026xxxx_add_hidden_quest.py`
   - `2026xxxx_add_notification.py`
   - `2026xxxx_add_onboarding.py`
   - `2026xxxx_add_task_proof_and_task_instance_fields.py`
   - `2026xxxx_add_stats_daily.py`
3. 每个迁移必须:
   - 提供 `upgrade()` / `downgrade()`
   - 在 CI 跑 `alembic upgrade head` + `alembic downgrade base` 双向验证
4. 字段变更(`add_column`)用 `op.add_column` + 默认值回填(若 NOT NULL)。
5. 新增枚举在应用层用 Pydantic 校验;DB 用 `VARCHAR(32)`,不引 MySQL ENUM(便于扩展)。

### 5.3 索引与性能

- 已在 19 张表的关键查询路径上加索引(`family_id` / `child_id` / `season_id` / `status` / `created_at`),
  本轮新增的表同样按此规则。
- `scn_stats_daily` 加 UNIQUE(`family_id`, `child_id`, `stat_date`)。
- `scn_task_proof` 在 `task_instance_id` 上加索引。
- 数据量预估: 单家庭 1-3 个孩子,每孩子每日 1-10 任务实例,一年单家庭任务实例 ~ 万级,
  时间币流水 ~ 十万级,均能轻松承载。

## 6. 数据生命周期(对应原"混合云存储策略")

- **原始证据文件** (图片/视频/音频): 默认**永久保留在对象存储**。
  - 新增"清理策略": `POST /scn/evidence/purge` 接收 `older_than_days`,
    将匹配的 `scn_task_proof.deleted_at` 置位,实际对象在 storage 层
    软删(标记,30 天后真删),DB 端用 `deleted_at IS NULL` 过滤展示。
- **任务实例与文案**: 永久保留 DB(数据价值高于成本)。
- **时间币流水**: 永久保留(分析需要)。
- **赛季结束**: 不物理删除 season / task_instance,改用 `is_active=False` +
  `end_date` 标记;`scn_privilege_unlock` 跨赛季不重置(与原设计"部分特权永久保留"一致)。

## 7. 种子数据(开发用)

在 `server/alembic/versions/..._seed_dev_data.py` 之外, 单独写一个
`server/scripts/seed_dev.py`, 提供:

- 1 个家庭 + 1 个 GuildMaster + 2 个 Adventurer
- 1 个当前激活的 Season (ThemeId.FROSTBOUND) + 1 个历史 Season
- 5 个 PrivilegeTemplate(Lv1/Lv3/Lv5/Lv8/Lv10)
- 6 个 TaskTemplateLibrary(STUDY/SPORT/CHORE/ART/LIFE)
- 1 个 Onboarding Path(3 步)

> 跑 `uv run python scripts/seed_dev.py` 即可,幂等。
