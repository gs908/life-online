# 04. 数值系统(经验值 + 时间币双体系)

> 本章定位:把"升级怎么算"和"时间币怎么扣"完整公式化,并把代码里要改/要加的点
> 列清楚。所有公式都是"产品可调 + 代码有测"的实现层接口。

---

## 1. 两套体系的一句话区分

| 体系 | 作用 | 持久化字段 | 体现 |
|---|---|---|---|
| **XP(经验值) / 等级** | 长期成长,与赛季主题叙事绑在一起 | `sys_child.xp` / `sys_child.level` | 升级条 / 升级动画 / 解锁特权 |
| **TimeCoin(时间币)** | 短期经济,任务押金币 | `sys_child.time_coin_balance` | 任务接取押金 / 放弃惩罚 / 每日重置 |

> **两套不互通**: 时间币不能换 XP,XP 也不能换时间币。
> 现实奖励 = 等级特权,不直接挂在币上。这是为了避免"完成任务 = 拿钱"的认知。

## 2. XP 与等级(本轮 v2 重点修订)

### 2.1 当前实现的问题

`server/app/services/xp_service.py`:

```python
def xp_needed_for_level(level: int) -> int:
    return max(level, 1) * 1000   # ← 线性 1000/L,违反"指数增长"初衷
```

问题:
- 升 10 级只比升 1 级难 10 倍,后期缺乏"稀缺感", 原需求"控制节奏,避免升级过快"做不到。
- 现实中后期孩子更需要"奖励落差"来维持挑战感。

### 2.2 新公式(指数)

```python
# 配置可调,默认 BASE_XP=200, GROWTH=1.5
def xp_required_for_level(level: int, *, base_xp: int = 200, growth: float = 1.5) -> int:
    """
    从 Lv L 升到 Lv L+1 所需 XP。
    level=1 → 200
    level=2 → 300
    level=3 → 450
    level=4 → 675
    level=5 → 1013
    level=10 → 3844
    level=15 → 14599
    """
    if level < 1:
        return base_xp
    return int(round(base_xp * (growth ** (level - 1))))
```

| Level | 累计 XP 升到此级 | 下一级所需 |
|---|---|---|
| 1 | 0 | 200 |
| 2 | 200 | 300 |
| 3 | 500 | 450 |
| 4 | 950 | 675 |
| 5 | 1,625 | 1,013 |
| 8 | 6,025 | 3,422 |
| 10 | 12,869 | 7,710 |
| 15 | 87,393 | 58,396 |
| 20 | 495,665 | 331,137 |
| 30 | 15,895,158 | 10,617,815 |

> 这个曲线确保:前 5 级一周内可达(给孩子成就感),
> 5-10 级需要 1-2 个月专注,10+ 级变成"长期目标"。

### 2.3 任务 XP 计算(落地到 `xp_service.calculate_xp`)

```python
def calculate_xp(
    base_xp: int,
    *,
    rating: int | None = None,
    started_at: datetime | None = None,
    submitted_at: datetime | None = None,
    required_start_time: time | None = None,
    is_challenge: bool = False,
    is_hidden: bool = False,
    chain_index: int | None = None,        # 1-based,链中位置
    chain_total: int | None = None,
    now: datetime | None = None,
) -> int:
    """
    最终 XP = base * rating_mul * timing_mul * speed_mul * chain_bonus
    """
    now = now or datetime.utcnow()
    mul = 1.0

    # 1) 星级系数(1-5 星)
    mul *= RATING_MULT.get(rating or 3, 1.0)
    # 5星 1.5, 4星 1.2, 3星 1.0, 2星 0.8, 1星 0.6

    # 2) 时效系数: 限时任务在 required_start_time 之前完成 → 1.2,
    #    之后完成 → 0.8;非限时任务 → 1.0
    if required_start_time is not None:
        deadline = datetime.combine(now.date(), required_start_time)
        mul *= 1.2 if now <= deadline else 0.8

    # 3) 速度系数: 60 分钟内完成 → 1.1
    if started_at is not None and submitted_at is not None:
        elapsed_min = (submitted_at - started_at).total_seconds() / 60
        if 0 < elapsed_min <= 60:
            mul *= 1.1

    # 4) 任务类型加成
    if is_challenge:
        mul *= 1.25
    if is_hidden:
        mul *= 1.15

    # 5) 连环任务链末加成
    if chain_index is not None and chain_total is not None and chain_index == chain_total:
        mul *= 1.5

    return int(round(base_xp * mul))
```

> **RATING_MULT** = `{1: 0.6, 2: 0.8, 3: 1.0, 4: 1.2, 5: 1.5}`(对齐原"5 星 1.5")。

### 2.4 升级判定

```python
def apply_xp_and_level(child: SysChild, xp_gained: int, *, base_xp=200, growth=1.5) -> dict:
    child.xp += xp_gained
    leveled_up = False
    levels_gained = 0
    while child.xp >= xp_required_for_level(child.level, base_xp=base_xp, growth=growth):
        child.xp -= xp_required_for_level(child.level, base_xp=base_xp, growth=growth)
        child.level += 1
        levels_gained += 1
        leveled_up = True
    return {
        "leveled_up": leveled_up,
        "levels_gained": levels_gained,
        "new_level": child.level,
        "current_xp": child.xp,
        "next_level_xp_required": xp_required_for_level(child.level, base_xp=base_xp, growth=growth),
    }
```

> 升级后会:
> 1. 触发 `privilege_service.unlock_for_user` 补齐该等级新解锁的特权;
> 2. 写一条 `scn_notification(LEVEL_UP)`;
> 3. 推送微信模板消息(若开通)。

### 2.5 软上限(本轮不做)

原设计提到"单日经验软上限"。本轮**不实现**,因为:
- 升级曲线已经指数化,后期升级极慢,自然限速;
- 时间币已经承担了"防止刷任务"的角色;
- 多加一层软上限反而增加家庭/孩子的认知负担。
- 后续如发现数据异常(单日 5000+ XP),再考虑加。

## 3. TimeCoin(时间币)

### 3.1 设计目标

- **不是奖励**: 孩子不会因为完成任务而"赚到币";
- **是押金**: 接任务时扣,完成时退,放弃时按规则罚;
- **每日重置**: 默认 100/天,可按星期配置例外,防止"币囤积 → 一次接 10 个任务"。

### 3.2 当前实现

`server/app/services/coin_service.py`:

```python
DEFAULT_DAILY_ALLOWANCE = 100

def calculate_deposit_fee(time_deposit: int) -> int:        # 接取时
    return time_deposit

def calculate_refund(deposit: int, abandon_count_today: int) -> int:  # 放弃时
    if abandon_count_today >= 3:
        return int(deposit * 0.6)   # 60% 退,40% 罚
    return deposit
```

### 3.3 本轮 v2 行为微调

1. **首次登录当日重置** — 已实现,保留。
2. **放弃任务退币规则** — 保留(连续 3 次后 60% 退)。
3. **新增: 限时任务超时未开始** → 自动放弃,扣 50% 押金(防止孩子挂着不开始)。
   - 在 `scn_task_instance` 加 `expire_at`,
   - 调度器每 5 分钟扫一次 `status=AVAILABLE` 且 `expire_at < now()` 的实例, 触发超时回收。
4. **新增: 押金不足时的体验** — 当 `time_coin_balance < time_deposit` 时,
   孩子端按钮禁用 + 弹"今日时间币用完,明天再来/完成更多基础任务赚币"提示
   (注: 完成基础任务**不**直接给币,只是退押金;币仍靠每日重置)。
5. **新增: 手动调整**(父母可补偿) — 走 `/scn/coins/adjust`,已实现 `coin_service.adjust_coins`。
6. **流水完整性** — 已落 `scn_time_coin_log`,每笔变更一条。

### 3.4 每日重置调度

`server/app/workers/scheduler.py`:

```python
scheduler.add_job(daily_reset_job, CronTrigger(hour=0, minute=5), id="daily_reset", ...)
```

本轮 v2 调整:
- `daily_reset_job` 当前**只对 `last_login_date != today` 的孩子重置**。
  实际"无论是否登录都重置"更合理(防止孩子不登录但仍接任务)。
- 改为: 每天 0:05 强制把 `time_coin_balance` 重置为当日配额(`default_daily_allowance` 或 `exceptions[weekday]`),
  `daily_abandon_count = 0`。
- `last_login_date` 仅用于 UI 提示"今日未登录",不再作为重置条件。
- 同时新增 `daily_aggregate_job`(0:30 跑),写 `scn_stats_daily`。

### 3.5 余额 vs 流水 vs 审计

| 表 | 用途 |
|---|---|
| `sys_child.time_coin_balance` | 当前余额,前端直接展示 |
| `scn_time_coin` | 冗余表,按 (family, child, season) 拆分(用于跨赛季审计/赛季结束迁移) |
| `scn_time_coin_log` | 全量流水,任意时点可重放对账 |

## 4. 任务押金(`time_deposit`)的设定原则

让家长在创建任务时直观选:

| 任务类型 | 默认押金 | 范围 |
|---|---|---|
| DAILY 日常 | 10 | 5-20 |
| CHALLENGE 挑战 | 30 | 15-50 |
| CHAIN 连环 | 单步 20 | 10-30 |
| TIMED 限时 | 25 | 15-40 |
| COOP 协作 | 5(分摊) | 0-20 |
| HIDDEN 隐藏(系统投放) | 0(惊喜) | 0 |

> 押金不能超过当日配额(避免孩子永远接不了),
> 创建任务时校验: `time_deposit <= default_daily_allowance / 2`(周末 200 时为 100)。
